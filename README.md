## 日期与提醒规则

1. 日期来自设备时钟，统一以 `Asia/Shanghai` 格式化；日期差按 UTC 日历日计算，避免夏令时误差。设备时间不准确时页面也会受影响。
2. 打开页面、跨日后的定时检查、回到前台时刷新日期。报告日期、家庭信息更新时间、来源查阅日期保持不变。
3. 估算孕周以 `estimatedDueDate - 280 天` 为起点，目前采用医院报告的末次月经 2026-04-25。医生后续校正预产期时，同时记录依据并审核未来安排。
4. 带 `pregnancyDays` 的任务随预产期调整日期，其他家庭行政计划保持原日期。临近参考结束日期 7 天以内为柔红，提醒期内为柔黄，后续为浅绿。
5. 原参考日期已过转入“历史待核实”，不自动判定漏检、已完成或要求补做。已完成、不适用状态优先于日期规则。
6. 出生后任务目前仅作计划，不把预产期当作真实出生日期；获得出生日期后需复核政策并更新任务。
7. 尚无出生记录且超过估算孕 42 周时，首页提示更新当前状态，不无限显示正在怀孕。这是记录保护，不是医学处置标准。
8. 报告专属随访使用 `reviewByDate` 记录预约／资料核对节点，临近时加重提醒；超过节点仍保留在当前事项，不解释为漏检。`pregnancyOnly` 在出生或当前状态待更新时停止孕期倒计时。节点按报告孕周换算，实际安排与医生确认日期另行登记。

这些操作移除当前版本的公开原图，不能删除已经进入 Git 历史或其他历史部署的副本。本次不改写 Git 历史；私密原件不随本次提交和发布上传。

## 本地预览和检查

仅当本机已有本次私密转录、并且需要重新导入核对结果时，先执行：

```sh
python3 scripts/import_angel_records.py
python3 scripts/import_angel_expenses.py
```

这两个命令需要本次导入的本地私密转录与核对清单。换设备只有匿名数据时，跳过导入命令即可；不要为构建页面而上传私密原件。

日常预览和检查在仓库根目录执行：

```sh
python3 scripts/build_site_data.py
node --test tests/timeline.test.cjs
python3 -m http.server 4173 --bind 127.0.0.1 --directory site
```

打开 <http://127.0.0.1:4173>。Windows 没有 `python3` 时可用 `python`。也可直接打开 `site/index.html`，数据通过普通脚本加载；以本地 HTTP 预览验证更稳妥。

默认访问密码仍为 `lyltm`，哈希集中在 `site/assets/app.js`。静态密码门只能防止随手访问，不能限制直接访问报告资源。需要真正保护高敏感电子报告时，可使用 Cloudflare Access。
